가장 흔한 실수 — schedule.html과 resume-download.js는 같은 웹앱 URL을 씁니다. URL이 바뀌면 두 파일 모두 고쳐야 합니다. (SCHEDULE_API_URL, RESUME_API_URL)

④ 실제 데이터가 도는 예시 — "어제 강의를 경력에 넣기"

  1. schedule.html에서 PIN 입력달력에서 지난 강의를 찾습니다.
  2. "경력등록" 버튼 클릭지난 날짜의 강의에만 버튼이 나타납니다.
  3. Apps Script가 변환해서 저장날짜 2026-05-26 → 2026.05.26, 학교+시수+주제를 합쳐 "주요업무" 한 칸으로 만들어 경력사항 시트에 추가합니다.
  4. 중복 방지 표시강의스케쥴 시트에 Y를 기록 → 달력에 "✓ 경력등록됨" 뱃지.
  5. 메인 페이지에 자동 반영index.html의 강의 경력 섹션과 경력서 PDF에 배포 없이 바로 나타납니다.
핵심 포인트 — 데이터만 바뀌는 일(경력 추가, 앱 등록, 자격증 입력)은 GitHub에 아무것도 올릴 필요가 없습니다. 시트를 저장하면 끝입니다. HTML/CSS/JS를 고쳤을 때만 배포가 필요합니다.

GitHub Pages 켜는 법 (최초 1회)

  1. GitHub에 저장소(repository) 만들기이름은 자유. 여기서는 profile.
  2. Settings → Pages 메뉴로 이동저장소 상단 톱니바퀴 메뉴입니다.
  3. Source: Deploy from a branch / Branch: main / 폴더: / (root)저장을 누르면 주소가 발급됩니다.
  4. 주소 확인https://아이디.github.io/저장소이름/ → 실제: loveria3.github.io/profile
  5. index.html이 자동으로 첫 화면파일 이름을 index.html로 두는 게 규칙입니다.

5 처음부터 똑같이 만들어보기

다른 분에게 설명할 때 이 순서대로 하면 됩니다. 유료 결제는 한 곳도 없습니다.

  1. 준비물 확인구글 계정 1개, GitHub 계정 1개, 텍스트 에디터(VS Code 등). 서버·도메인·카드 결제 전부 불필요.
  2. index.html 한 장부터 만든다소개 · 역량 · 자격 · 경력 4개 섹션에 id를 주고, 상단 메뉴에서 #id로 연결. 이 단계에서는 데이터를 HTML에 직접 써 둡니다.
  3. style.css로 색·폰트를 변수화CSS 변수(--bg, --accent …)로 정해두면 페이지를 늘려도 톤이 흐트러지지 않습니다.
  4. GitHub 저장소 만들고 Pages 켜기여기서 이미 인터넷에 공개된 사이트가 완성됩니다. 아직 DB는 없습니다.
  5. 구글 스프레드시트를 만들고 시트(탭)를 표로 설계탭 하나 = 테이블 하나. 첫 줄은 항상 컬럼명. 수정·삭제가 필요한 시트에는 ID 컬럼을 꼭 넣습니다.
  6. 확장 프로그램 → Apps Script로 API 만들기doGet()은 읽기, doPost()는 쓰기. action 값으로 add/update/delete를 나눕니다.
  7. 웹앱으로 배포하고 URL 복사실행: 나 / 액세스: 모든 사용자. 발급된 URL을 HTML 상단 상수에 붙여넣습니다.
  8. HTML에서 fetch로 불러와 화면 그리기HTML에 직접 써뒀던 데이터를 지우고 시트에서 받아온 값으로 교체. 여기서 "DB 연결 완료".
  9. 관리자 페이지를 PIN으로 막기정적 사이트라 완벽한 인증은 불가능합니다. 해시 + 시도 횟수 제한으로 가벼운 잠금 수준. 진짜 비밀은 담지 않습니다.
  10. 수정할 때마다 add → commit → pushGit 이력이 남아 되돌리기도 쉽습니다.
이 구조가 맞는 경우 개인 프로필, 포트폴리오, 소규모 목록 관리, 수업 자료실처럼 글 쓰는 사람은 나 하나, 읽는 사람은 여럿인 사이트.
이 구조가 안 맞는 경우 회원가입·로그인, 결제, 개인정보 저장, 동시에 여러 명이 쓰는 서비스 → 이때는 진짜 백엔드가 필요합니다.
